# Hardware, draft 0

A chip-level design of the [draft 0 ISA](isa-v0.md). It exists as a netlist
generated by Python ([emc/hw/cpu.py](../emc/hw/cpu.py)), not yet as
schematics or boards. Three tools work on it:

- a **netlist simulator** compiles it to C and runs programs with every
  chip modelled at its pins;
- a **static timing analysis** finds the cycle time from data-book delays;
- a **parts list** gives package counts and power.

| | |
|---|---|
| Pipeline | 5 stages (IF ID EX MEM WB), hardwired control, no microcode |
| Logic | MC10H ECL on −5.2 V; register file in 10E422 ECL RAM |
| Memories | 2 MB instruction, 2 MB data: 10 ns 5 V CMOS SRAM behind 10H translators |
| Packages | 710, plus the multiply/divide unit (not designed yet) |
| Cycle time, worst case | **30.7 ns, 32.6 MHz**; 27.6 ns (36.2 MHz) with ECLinPS pipeline registers |
| Power, worst case | about 300 W: 42 A at −5.2 V, 34 A into the −2 V termination rail, 2.6 A at +5 V |
| Verified | all 13 programs give the same output, registers and memory as the ISA simulator, in exactly the cycles the [pipeline model](../emc/pipeline.py) predicts |

```sh
python3 -m emc hw run sieve fib       # run programs on the netlist, compare with the ISA simulator
python3 -m emc hw sta                 # cycle time, strobe placement, critical paths
python3 -m emc hw sta --variants      # the same for the part variants
python3 -m emc hw bom                 # parts list, packages and power per block
```

`hw run` compiles the netlist with gcc into `build/` the first time.
It then simulates about 170,000 cycles a second.

## The pipeline

```
        IF              ID                    EX                  MEM               WB
  PC ─ IMEM ─┐   IR ─ decode            ┌ forward A/B/S ┐   EX/MEM ─ DMEM      MEM/WB ─┐
  PC+4       ├─▶   ─ hazards, stall ─▶  │ ALU, shifter  │ ─▶  load align   ─▶          │
  next PC ◀──┤     ─ RF read (2nd half) │ branch compare│     bus window              │
             │     ─ target, immediate  └ exceptions    ┘                              │
             └─── redirect: ID (predicted taken, jumps), EX (mispredicts, JALR) ◀──   RF write (1st half)
```

- **IF.** The PC addresses the instruction SRAMs through 10H125
  translators, and the word comes back through 10H124s.
  - The 10H124's complement outputs give the decoder the inverted
    opcode, function and sign bits for free.
  - The next PC is one 4:1 mux (10H174), choosing PC + 4, the ID-stage
    target, or the registered EX redirect. Its enable gives 0 at reset.
- **ID.** This stage does the most in parallel.
  - **Decode:** the opcode group enables 3-to-8 decoders built from NOR
    gates, so each instruction line is about three gate levels from IR.
  - **Hazards:** 10H166 comparators check the source fields against the
    destinations in EX and MEM. The forwarding selects for EX are worked
    out here and registered, so EX's muxes see settled selects.
  - **Interlock:** a stall is a load-use or SLT-use hazard, or a
    multiply/divide unit that is busy. It holds IF/ID and the PC by
    gating their clocks.
  - **Branch target:** a full adder computes PC + 4 + 4·offset.
  - **Prediction:** backward branches, J and JAL redirect fetch from ID,
    at the cost of one bubble. They do this even while stalled.
  - **Immediate:** one 4:1 mux picks the extended immediate, PC + 4 (the
    link value, or the not-taken path of a predicted-taken branch), the
    target (the taken path of a predicted-not-taken branch), or the LUI
    value.
  - **Register read:** the register file is read in the second part of
    the cycle.
- **EX.**
  - **Forwarding:** 4:1 muxes pick each operand from the register file,
    EX/MEM or MEM/WB (or the immediate).
  - **ALU:** 8 × 10H181 with two levels of 10H179 look-ahead.
  - **Funnel shifter:** three levels of muxes (by 16, by 4/8/12, by
    1/2/3) over a 63-bit input. The same muxes do `FSR`, `MFHI`, `MFLO`
    and `MFHL`. The shifter's outputs are wired-OR with the ALU's.
  - **Branch condition:** eight 10H166 magnitude comparators.
    - Six cover bits 0–29.
    - Two alternatives cover bits 30–31: one for unsigned compares, and
      one for signed compares with the two sign bits swapped.
    - A 10H164 8:1 mux picks the condition and XORs it with the
      prediction, which gives "mispredicted" directly.
  - **Exceptions:** misaligned addresses and jumps are worked out from
    the operands' low bits, not the adder output.
- **MEM.**
  - **Data SRAM:** four 512K×8 lanes. Byte and half stores enable only
    their lanes. Store data is replicated across the lanes in EX and
    driven onto the SRAMs' shared data pins by 3-state 10H601s.
  - **Load alignment:** one 10H164 per result bit, with sign extension
    folded into the mux inputs, so it costs no extra level.
  - **Main-bus window:** addresses with bit 31 set freeze the pipeline
    until `BUSDONE`.
- **WB.** MEM/WB writes the register file in the first part of the next
  cycle. The ID stage reads it later in the same cycle, so a value written
  in WB is seen by the instruction in ID with no extra forwarding.

**Penalties** (exactly those of the `p5` model in
[emc/pipeline.py](../emc/pipeline.py)):

| Event | Penalty |
|---|---|
| Load or SLT result used by the next instruction | 1 bubble |
| Predicted-taken branch, J, JAL | 1 bubble |
| Mispredicted branch, JALR | 3 bubbles |
| Multiply | 18 cycles; a dependent `MFHI`/`MFLO` waits |
| Divide | 34 cycles; a dependent `MFHI`/`MFLO` waits |
| Main-bus access | 20 cycles (a placeholder), the whole pipeline frozen |

Branch resolution sets the 3 bubbles. The branch condition is ready
about 25 ns into the cycle, so it goes through a register (`exr_q`) before
redirecting fetch. That costs one bubble more than redirecting from EX
directly, which would need the next-PC mux and the instruction-memory
address in the same cycle as well.

SLT results also arrive late, like loads. The less-than signal comes from
the comparators and is merged into the result in MEM.

## Clocking

- **One clock edge per cycle,** with no two-phase logic. The clock is
  asymmetric: low for the last 4 ns of each cycle.
- **Gated clock domains:** each domain's clock is `CLK OR hold`, from
  10H210 clock fan-out gates with 4 loads per output. A hold signal must
  settle while the clock is high, which the timing analysis checks.

  | Domain | Held by | Clocks |
  |---|---|---|
  | `p` | bus freeze, halted, exception in MEM | pipeline registers |
  | `f` | as `p`, or a stall | IF/ID |
  | `pc` | as `p`, or a stall with no redirect due | the PC |
  | `u` | never | the halt flag, the multiply/divide unit |

- **Strobes,** at fixed times after the edge. They need a multi-phase
  clock or a delay line (see [parts.md](parts.md#clock)). The timing
  analysis places each one as early as its constraints allow:

  | Strobe | What it does | Timing, all-10H design |
  |---|---|---|
  | `RFSEL` | register-file address mux: the write address (MEM/WB destination) until `t_rd`, then the read addresses | read addresses from 16.15 ns |
  | `RFWS` | register-file write strobe, gated by "writes a register" | 7.50–13.30 ns |
  | `MWS` | data-memory write strobe, gated per lane | 6.80–22.70 ns |

The register file is two copies of 8 × 10E422 (256×4 RAM; only the low 32
words are used). Each copy serves one read port, and both are written
together. A 10E422 has one address port, so the write happens in the first
part of the cycle and the read in the second. That is the main reason the
register-file path is the critical one (see below).

| mem | 123 | 37 | load alignment (25 × 10H164), result and bus-read gating (10H188), translators, store-data forwarding |
| shifter | 94 | 34 | 68 × 10H174, 10H158 |
| decode | 89 | 7 | 87 × 10H109: decoders and class logic |
| idex | 70 | 22 | ID/EX register (10H176), its control logic, hold-time buffers |
| fetch | 59 | 30 | PC, PC + 4 (10H181), next-PC mux, IMEM translators |
| forward | 58 | 22 | operand muxes (52 × 10H174) |
| branch | 41 | 12 | 8 × 10H166, the merge logic, the redirect-address mux |
| exmem | 33 | 13 | EX/MEM register |
| imm | 23 | 7 | immediate mux |
| regfile | 21 | 14 | 16 × 10E422, address muxes |
| hazard | 18 | 4 | 10H166 as equality comparators |

| other | 38 | 10 | the 8 SRAMs, clock gating, store-data replication, exceptions, halt |

The muxes are the biggest item: 234 packages, a third of the machine.

- **Shifter:** a 32-bit barrel shifter in 2-bit-wide 10H174s takes 68 of
  them.
- **Forwarding:** each forwarded 32-bit operand takes 16.

The [design notes](design-notes.md#3-rough-sizes) expected this.

## Timing

[emc/hw/sta.py](../emc/hw/sta.py) is a block-based static timing
analysis.

- **Delays:** every arc is the data-book maximum at 75 °C, for −5.2 V
  ±5 % and 50 Ω to −2 V loads.
- **Wires:** 0.3 ns for a net inside one block and 0.75 ns between
  blocks (about 2 and 5 inches of microstrip). TTL-side nets get 0.45 ns
  more. Each load adds 0.1 ns, each extra wired-OR output 0.05 ns.
- **Clock:** 0.5 ns of skew is subtracted from every setup check and
  added to every hold check.
- **Strobes:** placed first, as above. Then every flip-flop input, the
  clock-gating inputs and both memories' write constraints set the cycle
  time.

| Variant | Cycle | Clock |
|---|---:|---:|
| All 10H, 10E422-7 (the netlist as it is) | 30.70 ns | 32.6 MHz |
| … with the 5 ns 10E422 grade | 30.35 ns | 32.9 MHz |
| Pipeline registers MC10E151 (ECLinPS) instead of 10H176 | 27.60 ns | 36.2 MHz |
| MC10E151 and the 5 ns 10E422 | 27.40 ns | 36.5 MHz |

The E151 is a drop-in timing change here: clock-to-Q 0.8 ns instead of
2.4, setup 0 instead of 1.5. On a board it is a different package
(PLCC-28), and the 10H-level version costs about $36 (see
[parts.md](parts.md#eclinps-mc10e--mc100e-the-speed-option)).

### Where the time goes

The design is balanced. Its longest paths are all within about 2 ns of
each other, so no single fix gets much:

| Path | All 10H | What it is |
|---|---:|---|
| Register-file read | 30.70 | `RFSEL` at 16.15 ns (after the write) → address mux 2.9 → 10E422 7.0 → ID/EX setup |
| Load | 30.35 | EX/MEM 2.4 → 10H125 3.4 → SRAM 10.0 → 10H124 2.95 → alignment mux 2.6 → MEM/WB setup |
| Branch resolution | 29.75 | forwarding mux → 10H166 4.1 → carry-style merge of 7 comparators → 10H164 → `exr` register |
| Data-memory write | 29.00 | `MWS` must end before the address can change |
| Branch target | 28.95 | IF/ID 2.4 → target adder 14.7 (10H181, two 10H179 levels, 10H181) → immediate mux 2.6 → ID/EX; and → next-PC mux → PC (28.50) |
| Decode | 28.90 | IR → group enable → decoder → class OR trees → destination logic → ID/EX: 10 gate levels |
| Exceptions | 28.45 | forwarding mux → misalignment → exception → EX/MEM |

The time-multiplexed register file costs about 16 ns of every cycle
before the read can start. To get to 40 MHz (25 ns), these would each
need work:

- **ECLinPS registers** take about 3 ns off every path (above).
- **Register file:**
  - Read in the first half and write in the second, with a third
    forwarding path from WB. That needs a latch for the read data.
  - Or use the 5 ns 10E422.
- **Load path:**
  - Move load alignment into WB (−2.6 ns, at the cost of the forwarding
    path from WB).
  - Or use MC100EPT25 translators for the addresses (−1.8 ns).
- **Branch condition:** better comparators, for example the 9-bit
  MC10E166 (1.4 ns against 4.1, and four instead of eight).
- **Branch target:** an adder for the 16-bit branch offset alone, with
  the top half as an incrementer or decrementer chosen by the carry
  (carry-select), would take several ns off.

### Hold times

The 10H176's minimum clock-to-Q (0.9 ns) is less than its hold time
(1.0 ns) plus the 0.5 ns of skew.

- **Problem:** every direct register-to-register path fails hold, for
  example PC + 4 passing from IF/ID to ID/EX.
- **Fix:** `sta.fix_hold` adds a 10H101 OR section (0.5 ns minimum) in
  front of each failing input: 82 sections, 22 packages. Tight clock
  distribution can't be relied on to avoid this.
- **E151 registers:** hold 0.35 ns, so only 3 buffers are needed.

## The multiply/divide unit

The MULDIV block is still behavioural:

- radix-4 Booth multiply in 18 cycles;
- radix-2 non-restoring divide in 34 cycles;
- `HI` and `LO` registers, `MADD`, `MTHI` and `MTLO`.

Its interface is final:

- it starts from EX when the pipeline is not frozen;
- it reports `BUSY`;
- every instruction of the multiply/divide group (`MFHI`, `MFLO`,
  `MFHL`, `MTHI`, `MTLO`, another multiply) waits in ID while the unit
  is busy.

[evaluation-v0.md](evaluation-v0.md) argues for a much faster one.

## What isn't designed

- **The multiply/divide unit** (above).
- **The main-bus interface.** The netlist has a placeholder: `BUSDONE`
  and `BUSRD` come from the testbench, which answers after 20 cycles.
  Nothing yet drives the bus.
- **The host interface:** loading the memories, starting and stopping,
  reading the stop cause.
- **The clock and strobe generator.** The netlist takes `CLK`, `RFSEL`,
  `RFWS_N` and `MWS_N` as inputs.
- **Physical design:**
  - boards, the backplane, connectors;
  - termination, decoupling and power distribution;
  - real wire lengths. The wire model above is an estimate.
- **Reset.** `RESET` is held for a few cycles. It clears the pipeline's
  valid bits, sets the PC to 0 and writes 0 to `r0`. Nothing else is
  initialised.
